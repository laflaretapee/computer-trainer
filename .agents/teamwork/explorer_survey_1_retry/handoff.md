## 2. Logic Chain (Логическая цепочка рассуждений)

1. **Модель исполнения приложения:**
   Поскольку в `index.html` данные подключаются через теги `<script src="data/students.js">` и `<script src="data/content.js">`, данные инициализируются синхронно в глобальной области видимости `window.STUDENTS_DATA` и `window.CONTENT_DATA`. Это сделано намеренно, чтобы тренажёр запускался прямо через протокол `file:///` двойным кликом по `index.html` в проводнике Windows без необходимости поднимать локальный веб-сервер (так как современные браузеры блокируют `fetch()` к локальным JSON-файлам по политике CORS при протоколе `file://`).

2. **Оценка автономности (Offline-First):**
   Все зависимости (стили, скрипты, картинки слайдов, шрифты, шрифтовые глифы emoji) замкнуты внутри локальной файловой системы. Ни одного сетевого запроса при загрузке или работе тренажёра браузер не производит. Следовательно, требование R2 соблюдается на 100%.

3. **Анализ дополнительного требования автообновления:**
   Требование: «an auto-update mechanism that checks for updates when an internet connection becomes available (via navigator.onLine or update manifest check), while maintaining 100% stable offline operation when disconnected».
   - Если приложение открыто через `file://`:
     Вызов `fetch('https://...')` при наличии сети технически возможен, но вызов `fetch('manifest.json')` относительно локальной папки заблокируется политикой CORS браузера (`Fetch API cannot load file://...`).
     Кроме того, сервис-воркеры (`navigator.serviceWorker.register`) **не работают** на протоколе `file://` (браузеры требуют безопасный контекст `https://` или `http://localhost`).
   - Если приложение развёрнуто по локальной сети / HTTP:
     Сервис-воркер и сетевой fetch работают штатно.
   - **Архитектурное решение автообновления:**
     1. Проверка доступности сети: проверка флага `navigator.onLine` и подписка на события `window.addEventListener('online', ...)` и `window.addEventListener('offline', ...)`.
     2. Проверка контекста запуска: `const isHttp = location.protocol.startsWith('http');`.
     3. Неблокирующий безопасный опрос манифеста обновления:
        При появлении сети или по таймеру (раз в 15–30 минут), ТОЛЬКО если `navigator.onLine === true`, выполняется `fetch()` к внешнему или локальному манифесту (например, `update-manifest.json` или удаленному API) с `AbortController` и таймаутом 2500 мс.
     4. Изоляция ошибок (Fail-Safe): весь процесс обёрнут в `try/catch`. Если сеть пропала в момент запроса, DNS не резолвится или сервер недоступен, ошибка поглощается без вывода пугающих модальных окон или консольных ошибок. Приложение остаётся на 100% функциональным в офлайне.
     5. UI-индикация обновления: если манифест вернул версию выше текущей (`remoteVersion > LOCAL_VERSION`), в нижней или верхней панели ненавязчиво отображается плашка: «Доступно обновление X.X.X. Перезагрузите страницу для применения».

4. **Интеграция новых модулей (Мышь, Клавиатура, Геймификация):**
   Архитектура модулей в проекте построена по принципу IIFE с экспортом в `window`:
   - `modules/typing.js` -> `window.TypingTrainer`
   - `modules/teacher.js` -> `window.TeacherPanel`
   - Рекомендуется аналогично создать `modules/mouse.js` -> `window.MouseTrainer`
   - Для сохранения прогресса в `app.js` используется централизованный метод `App.saveProgress(studentId, module, data)`, который пишет в `localStorage` по ключу `trainer_progress`. При внедрении модуля мыши и геймификации достаточно расширить схему хранения:
     `record.mouse = { sessions: [], score: 0, completedTasks: [] };`
     `record.gamification = { xp: 0, level: 1, achievements: [] };`
   Это полностью сохранит обратную совместимость с уже существующими записями 79 учеников.

## 3. Caveats (Ограничения и допущения)

1. **Протокол `file://` vs HTTP для автообновления:**
   В браузерах на базе Chromium (Chrome, Edge, Яндекс.Браузер) Service Worker не регистрируется на протоколе `file://`. Механизм автообновления через Service Worker Cache может активироваться только при работе через локальный веб-сервер (`http://localhost:8000`). Для режима `file://` проверка обновления возможна только через удалённый HTTPS-эндпоинт манифеста, если у компьютера появляется внешний интернет, а само обновление кода в автономной папке требует ручной замены файлов либо локального апдейтера.
2. **Синхронизация слайдов презентаций:**
   Слайды в `indexed/` зафиксированы в PNG. Если учитель добавит новые презентации в `presentations/grade7/`, необходимо запустить `python index_presentations.py` и затем `python build_content_js.py`.
3. **Хранилище прогресса (LocalStorage):**
   LocalStorage привязан к конкретному браузеру на конкретном компьютере. В компьютерном классе каждый ПК хранит успеваемость тех учеников, которые работали за этим ПК. Экспорт в CSV в модуле `teacher.js` позволяет учителю собирать отчёты со всех ПК.
